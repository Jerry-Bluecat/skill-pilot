# 交接卡：检查更新——基准不可靠时不翻历史

> 2026-10-11 由 Claude（主控）派给 Codex。上一轮 `docs/fix-update-check-report.md`。只做本卡内容。

## 问题

上一轮真实只读检查中，`huashu-nuwa`、`agent-reach` 两个仓库超过 60 秒限时，显示“没查成，可以稍后重试”；重试会同样超时。用户正等着用新版看板更新 huashu-nuwa。原因：这两个技能的基准不可信，检查时要翻上游历史校准基准（agent-reach 上游有 40 多个历史版本，nuwa-skill 也逐个拉取）。

## 修正

PLAN §1 已定“本机改过的技能默认用上游的”，检查阶段不必为了判断“你改过没有”而翻历史：

- 基准不可信时，检查只做一件事：取上游当前版本（经嵌套 SKILL.md 改名等标准处理后）与本机内容比较。相同 → 已是最新；不同 → 列为“有更新”，并标注“无法判断你是否改过，默认用上游的”。不再翻历史校准。
- 用户点“更新”（用上游的）时，把上游当前版本写为新基准，下次检查即可走 tree sha 的快速比较。
- 历史校准只在用户在该条上主动选“保留我的”或点“交给 Codex 合并”时才进行（需要三方对比时），并单独给更长时限，界面显示“正在找你改过的地方…”。
- 删除因此不再需要的检查期校准代码。

## 范围与约束

- **可写**：`~/Developer/skill-pilot/`（不要 commit、push）、系统临时目录。
- **只读**：真实 home 的一切；对真实 home 运行本工具一律带 `SKILL_PILOT_READ_ONLY=1`；不要启动或干扰用户的看板进程；不改启动器。
- `skill_pilot/` 代码总行数（`find skill_pilot -name "*.py" -o -name "*.js" -o -name "*.html" | xargs wc -l`，当前 4,442）**不得增加**。
- 测试里凡是启动看板服务的，单实例锁和端口要用测试自己的临时目录，避免与其他正在运行的看板或测试服务抢锁（主控上一轮验收时，首次全量单测卡住 10 分钟，第二次 38 秒通过，疑为抢锁）。

## 验收

- 真实 home 只读检查一次：huashu-nuwa 和 agent-reach 都给出明确结果（有更新 / 已是最新），不再超时；记录总耗时。
- 模拟 home：基准不可信的技能检查时不翻历史（可用计数替身证明）；点“更新”后写入新基准，再查走快速比较；选“保留我的”才触发校准。
- 全量单测在另一个看板实例运行时也能通过。主控会对比真实 home 指纹。
